H06

Windows の短い名前（8.3）で Claude Code に Write・Edit させると、元のファイル名が消える

Claude Code ファイル名 変わる · Claude Code 8.3 短い名前

症状

app.settings.json や credentials.json が消えて、APPSET~1.JSO や CREDEN~1.JSO という名前のファイルができている。中身は Claude が書いたとおり。ツールはふつうに成功と返していて、名前が変わったことは言っていない。

30秒で確かめる

PowerShell（Windows PowerShell 5.1）に貼って実行します。一時フォルダ（%TEMP% の下）にだけファイルを作ります。最後に REPRODUCED と出たら、あなたの PC で起きています。 claude を1回呼ぶので、1分ほどかかります。

$d = Join-Path $env:TEMP ('cc-trap-' + (Get-Date -Format 'yyyyMMddHHmmss')); New-Item -ItemType Directory $d -Force | Out-Null
Set-Content -LiteralPath "$d\app.settings.json" -Value old
$short = (cmd /c dir /x "$d" | Select-String 'app\.settings\.json' | ForEach-Object { ($_.Line -split '\s+') | Where-Object { $_ -match '~[0-9]' } } | Select-Object -First 1)
if (-not $short) { 'CANNOT CHECK (no 8.3 short name on this drive: dir /x shows none, so this cannot happen here)' } else {
"short name: $short"
Push-Location $d
"Use the Write tool once to overwrite the file $short in the current folder with the single line new. Use exactly that file name. Do not use any other tool. Do not retry." | claude -p --permission-mode bypassPermissions | Out-Null
Pop-Location
$long = Test-Path -LiteralPath "$d\app.settings.json"
$names = (Get-ChildItem -LiteralPath $d -Force | ForEach-Object { $_.Name }) -join ', '
"after the write: files = $names"
if ((-not $long) -and ($names -match [regex]::Escape($short))) { 'REPRODUCED' } else { 'NOT REPRODUCED' }
}

なぜ起きるか

Windows のファイルには、長い名前とは別に dir /x で見える短い名前（8.3 形式）が付いていることがある。同じファイルの別名だが、Claude Code の Write・Edit にこの短い名前を渡すと、長い名前のファイルが消え、短い名前そのもののファイルが作られる（公式 issue #110153）。acceptEdits の claude -p では止まったが、確認なしで書き込む bypassPermissions では起きる。

直し方

bypassPermissions は使い捨ての環境だけにする。普段の PC で使うなら、ファイル名の部分に ~数字 があるパスを拒否する PreToolUse フックを入れる（-File で呼び、onFailure: block も付ける）。

$p = [string]$j.tool_input.file_path
if ((Split-Path $p -Leaf) -match '~[0-9]+') { [Console]::Error.WriteLine('blocked: 8.3 short name'); exit 2 }
