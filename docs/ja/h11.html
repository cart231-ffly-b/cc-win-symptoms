Windows の Claude Code の Bash ツールで、%TEMP% の下への cd が次の呼び出しで取り消される

Claude Code Shell cwd was reset · Claude Code cd 戻る Temp

症状

Bash ツールで %TEMP%（AppData\Local\Temp）の下のフォルダに cd したのに、次の呼び出しでは元のフォルダに戻っていて、「Shell cwd was reset to ...」と出る。同じ場所でも Temp 以外の隣のフォルダ（AppData\Local\Microsoft など）への cd は残る。

30秒で確かめる

PowerShell（Windows PowerShell 5.1）に貼って実行します。一時フォルダ（%TEMP% の下）にだけファイルを作ります。最後に REPRODUCED と出たら、あなたの PC で起きています。 claude を1回呼ぶので、1分ほどかかります。

$d = Join-Path $env:TEMP ('cc-trap-' + (Get-Date -Format 'yyyyMMddHHmmss')); New-Item -ItemType Directory $d -Force | Out-Null
New-Item -ItemType Directory "$d\sub" -Force | Out-Null
$u = $d -replace '\\', '/'
$p = 'Use the Bash tool exactly twice, one command per call. Call 1: cd "U/sub" && pwd > "U/p1.txt" . Call 2: pwd > "U/p2.txt" . Then stop.'.Replace('U', $u)
Push-Location $d
$p | claude -p --allowedTools Bash | Out-Null
Pop-Location
if (-not (Test-Path "$d\p1.txt") -or -not (Test-Path "$d\p2.txt")) { 'CANNOT CHECK (the Bash tool did not run both calls: check that it is available and allowed)' } else {
$p1 = (Get-Content "$d\p1.txt" -Raw).Trim(); $p2 = (Get-Content "$d\p2.txt" -Raw).Trim()
"inside %TEMP%: same call after cd sub -> $p1 ; next call -> $p2"
if (-not $p1.EndsWith('/sub')) { 'CANNOT CHECK (cd did not work even inside the same call)' } elseif (-not $p2.EndsWith('/sub')) { 'REPRODUCED' } else { 'NOT REPRODUCED' }
}

なぜ起きるか

Windows の Claude Code の Bash ツールは、呼び出しのあとの作業フォルダが %TEMP% の下だと、起動したフォルダに戻す（公式 issue #110213）。同じ呼び出しの中なら cd は効くので、1回目の呼び出しは正しく動き、2回目から黙って別の場所で動く。

直し方

作業フォルダは呼び出しごとに指定する（絶対パスを使うか、cd と実行を同じ呼び出しに入れる）。使い捨ての作業場所を %TEMP% の下に作るなら、毎回そのフォルダの絶対パスで書く。Claude Code 自身にこう書かせる CLAUDE.md の型は、本の9章（CLAUDE.md の型を読む（Zenn・全章 1,200円／0〜4章は無料） ）にある。

cd "C:/Users/me/AppData/Local/Temp/work" && ./run.sh   # cd と実行を同じ呼び出しに
