Claude Code の PowerShell ツールは、途中のコマンドの終了コードで、成功を「失敗」と返す

症状

Claude Code が PowerShell ツールで robocopy などを動かすと、コピーはできているのに Exit code 1 の失敗として返り、Claude がやり直したり、コマンドを書き換えたりする。最後の文は成功している。

30秒で確かめる

PowerShell（Windows PowerShell 5.1）に貼って実行します。一時フォルダ（%TEMP% の下）にだけファイルを作ります。最後に REPRODUCED と出たら、あなたの PC で起きています。 claude を1回呼ぶので、1分ほどかかります。

$d = Join-Path $env:TEMP ('cc-trap-' + (Get-Date -Format 'yyyyMMddHHmmss')); New-Item -ItemType Directory $d -Force | Out-Null
[IO.File]::WriteAllText("$d\s.json", '{"env":{"CLAUDE_CODE_USE_POWERSHELL_TOOL":"1"}}')
Push-Location $d
$out = "You must use the PowerShell tool (not Bash). Run exactly the PowerShell command in the next line once, then stop.`ncmd /c exit 3; 'done'" | claude -p --settings s.json --allowedTools PowerShell --output-format stream-json --verbose | Out-String
Pop-Location
$ran = $out -match 'done'
$err = $out -match '"is_error":true'
"the PowerShell tool ran the command: $ran; the call was reported as an error: $err"
if (-not $ran) { 'CANNOT CHECK (the PowerShell tool did not run: check that claude -p can use it)' } elseif ($err -and ($out -match 'Exit code 3')) { 'REPRODUCED' } else { 'NOT REPRODUCED' }

なぜ起きるか

PowerShell では、外のプログラムの終了コードが $LASTEXITCODE に残る。PowerShell ツールは、最後に残った $LASTEXITCODE を呼び出し全体の結果として返す（公式 issue #97589）。ふつうの powershell -Command や -File では、同じコマンドの終了コードは 0 になる。robocopy は成功でも 1〜7 を返す。

直し方

成功でも 0 以外を返すコマンド（robocopy・findstr・git diff --quiet など）のあとは、終わりに exit 0 を付け、終了コードは文字で出す。本当の失敗も失敗扱いにならなくなるので、出した exit= の行を読ませる。終了コードの穴は本の3章（https://zenn.dev/kamijo_aoto/books/windows-claude-code-traps ）にもある。

robocopy src dst a.txt | Out-Null; $rc = $LASTEXITCODE; if ($rc) { "exit=$rc" }; exit 0

作者の PC での結果

PowerShell ツールで cmd /c exit 3; 'done' は done まで動いたのに is_error=true・Exit code 3。robocopy で1つコピーしても Exit code 1 の失敗（コピーはできていた）。; exit 0 を足すと失敗にならない。ふつうの powershell -Command と -File では 0（2026-11-25、Claude Code 2.1.330、Windows PowerShell 5.1）

作者の PC: Windows 11 / Windows PowerShell 5.1.26100 / Python 3.13.7 / Claude Code 2.1.304、日本語の Windows（コードページ 932）。2026-10-20〜22 に確認。

部品の実装と設計を書いた本（Zenn、1,200円。0〜4章は無料）

ほかの症状

  • PowerShell の終了コードが、2 を返したのに 1 になる
  • -File で渡した2つ目の引数が、エラーなしで消える
  • -File で a,b と渡すと、配列にならず1つの文字列になる
  • パイプで渡した日本語が ? になる（claude -p・python・git）
  • python や claude の出力を変数に入れると文字化けする
  • 手で動かすと通る Python が、タスクスケジューラやリダイレクトのときだけ落ちる
  • PYTHONIOENCODING を設定したのに、python -I だと効かない
  • 日本語入りの .ps1 が、構文エラーになるか文字化けして動く
  • .cmd / .bat のコメントが、コマンドとして実行される
  • powershell -Command の1行に書いた $変数 が、呼ぶ前に消える
  • Get-ChildItem の -Include が効かず、全部のファイルが返る
  • "..." に書いた Markdown のバッククォートで、文字が消えて改行が入る
  • 書き込み中のログが 0 バイトに見える
  • claude -p --allowedTools の後ろに書いたプロンプトが飲み込まれる
  • Claude Code の PreToolUse フックが、時間切れになると書き込みを止めずに通す
  • PowerShell のフックを -Command で呼ぶと、Claude Code の拒否が素通りする
  • Claude Code のフックが1つも動かない（disableAllHooks が残っている）
  • Python で書いた Claude Code の拒否フックが、日本語のフォルダでだけ書き込みを通す
  • Claude Code のフックのパスを \ で書くと、フックが起動せず書き込みが通る（終了コード 127）
  • Windows の短い名前（8.3）で Claude Code に Write・Edit させると、元のファイル名が消える
  • Claude Code で裏の Bash を TaskStop で止めても、& やパイプで動かしたプロセスが残る
  • claude -w -p が終わったあとも、git の worktree のロックが残って消せない
  • Claude Code の Bash ツールで、$$( を含むコマンドが「削除の安全確認」で止まる
  • Windows の Claude Code の Bash ツールで、\\（バックスラッシュ2つ）が \ 1つになる
  • Claude Code の PowerShell ツールで、cd したフォルダが次の呼び出しで元に戻る
  • Windows の Claude Code の Bash ツールで、%TEMP% の下への cd が次の呼び出しで取り消される
  • claude -p の --json-schema が、道具を絞った --agent を付けると黙って効かない（成功のまま）
  • サブフォルダの CLAUDE.md を一部だけ Read すると、残りが黙って読み込まれなくなる
  • リポジトリのサブフォルダで Claude Code を起動すると、ルートの .claude/settings.json のフックが効かない
  • ジャンクションの下で Claude Code を起動すると、作業フォルダが本当のパスに置き換わる（フックにも）
  • Windows の Claude Code の Bash ツールは、7,400 文字ほどを超えるコマンドを動かさない（エラーは「引用符が閉じていない」）
  • フックの .ps1 が見つからないと、onFailure: block でも書き込みが通る
  • Windows の Claude Code で Edit・Write すると、ファイル名の大文字小文字が黙って変わる
  • Git Bash のフックで $PWD と file_path を比べると、Windows ではプロジェクトの中まで「外」になる
  • Windows の Claude Code は、パスのドライブ文字が小文字（c:\）だと、下のフォルダの CLAUDE.md を読まない
  • Claude Code の Edit・Write は、.md 以外のファイルで行末の空白を黙って消す（タブを空白に置き換えると、消えるだけ）
  • Claude Code の Grep は、作業フォルダの下を探すとき、glob の */ が「見つからない」になる
  • Codex CLI が PowerShell 5.1 でパイプに渡した日本語が ? になる（終了コード 0）
  • Codex CLI が PowerShell 5.1 で読んだ UTF-8（BOM なし）の日本語が化ける（終了コード 0）
