Windows の日本語文字化けまとめ｜PowerShell・Python・Claude Code・Codex CLI

パイプで日本語が ? になる、cp932 で UnicodeEncodeError が出るなど、見た目から原因と直し方を探せます。

手元の PC でどの症状が再現するかをまとめて確かめる。doctor.ps1 の診断コマンドを表示

文字化けの見た目から探す

見た目症状ページ原因と直し方
? になるPowerShell のパイプで渡した日本語が ? になる（claude -p・python・git）

Windows PowerShell 5.1 は、ネイティブのプログラムへパイプで渡す文字を $OutputEncoding で符号化する。既定は ASCII なので、日本語は ? になる。

長い日本語は UTF-8 のファイルに書き、ASCII だけの指示で「このファイルを読んで」と渡す。保険として $OutputEncoding を UTF-8 にする。

? になるCodex CLI が PowerShell 5.1 でパイプに渡した日本語が ? になる（終了コード 0）

PowerShell 7 が無いと、Codex は powershell.exe（5.1）の -Command でコマンドを動かす。5.1 は外部のコマンドに渡す文字を $OutputEncoding で符号化し、その既定が ASCII なので、ASCII にない文字はすべて ? になる（公式 issue openai/codex #64139）。

パイプの前に $OutputEncoding を UTF-8 にする。Codex に任せるなら、プロジェクトの AGENTS.md に「パイプの前に $OutputEncoding を UTF-8 にする」と書く（効きやすくなるが、確実ではない）。

「譌･譛ｬ」「繝｡繝｢」のように化けるPowerShell で python や claude の出力を変数に入れると文字化けする

PowerShell はネイティブのプログラムの出力を [Console]::OutputEncoding（日本語の Windows では既定 932）で読む。相手が UTF-8 で書いていると、読み違える。

出力を読む側で [Console]::OutputEncoding を UTF-8 にする。送る側の Python は PYTHONIOENCODING を utf-8 に（次の T06）。両方そろえる。

「譌･譛ｬ」「繝｡繝｢」のように化けるCodex CLI が PowerShell 5.1 で読んだ UTF-8（BOM なし）の日本語が化ける（終了コード 0）

PowerShell 7 が無いと、Codex は Windows PowerShell 5.1 の Get-Content でファイルを読む。

読むときに -Encoding UTF8 を付ける。Codex に任せるなら、プロジェクトの AGENTS.md に「Get-Content は -Encoding UTF8 で」と書く（効きやすくなるが、確実ではない）。

UnicodeEncodeError で落ちる手で動かすと通る Python が、タスクスケジューラやリダイレクトのときだけ UnicodeEncodeError（cp932）で落ちる

Windows の Python は、出力先が画面なら Unicode をそのまま書けるが、ファイルやパイプだと既定のコードページ（日本語なら cp932）で符号化する。その表に無い文字で落ちる。

送る側で PYTHONIOENCODING=utf-8 を設定する。アプリで直すなら、画面でないときだけ sys.stdout.reconfigure(encoding='utf-8')。

UnicodeEncodeError で落ちるPYTHONIOENCODING を設定したのに、python -I だと効かない

-I（隔離モード）は PYTHON で始まる環境変数をすべて無視する。

-I を外すか、スクリプトの中で sys.stdout.reconfigure(encoding='utf-8') を呼ぶ。

構文エラーになるか、化けた文字を出すPowerShell 5.1 で日本語入りの .ps1（BOM なし UTF-8）が、構文エラーになるか文字化けして動く

Windows PowerShell 5.1 は、BOM の無い .ps1 を UTF-8 ではなく ANSI コードページ（日本語なら 932）として読む。今のエディタの多くは BOM なしの UTF-8 で保存する。

日本語を含む .ps1 は UTF-8（BOM 付き）で保存する。または .ps1 を ASCII だけで書き、日本語は [char]0x65E5 のように組み立てる。

日本語のフォルダで拒否フックが素通りするPython で書いた Claude Code の拒否フックが、日本語のフォルダでだけ書き込みを通す

Claude Code はフックの標準入力に UTF-8 の JSON を送る。日本語 Windows の Python は、標準入力が端末でないとき cp932 で読むので、json.load(sys.stdin) が日本語のパスで JSONDecodeError（Invalid \escape）になる。

標準入力をバイト列のまま読んで UTF-8 で解く。あわせて "onFailure": "block" を付ける（直す前のフックのままでも、これで止まった）。拒否の理由は ASCII で出す（json.dumps の既定のまま）。
