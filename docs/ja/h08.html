H08

claude -w -p が終わったあとも、git の worktree のロックが残って消せない

claude -w worktree locked · git worktree remove locked claude session

症状

claude -w で作った worktree を git worktree remove で消そうとすると「locked working tree」と断られる。git worktree prune でも残る。claude -p は終了コード 0 で終わっている。夜に回すたびに worktree が溜まっていく。

30秒で確かめる

PowerShell（Windows PowerShell 5.1）に貼って実行します。一時フォルダ（%TEMP% の下）にだけファイルを作ります。最後に REPRODUCED と出たら、あなたの PC で起きています。 claude を1回呼ぶので、1分ほどかかります。

$d = Join-Path $env:TEMP ('cc-trap-' + (Get-Date -Format 'yyyyMMddHHmmss')); New-Item -ItemType Directory $d -Force | Out-Null
Push-Location $d
git init -q 2>$null
git -c user.name=t -c user.email=t@example.invalid commit -q --allow-empty -m init 2>$null
'Reply with the single word OK.' | claude -w e1 -p | Out-Null
$list = git worktree list --porcelain 2>$null | Out-String
Pop-Location
$wt = ([regex]::Matches($list, '(?m)^worktree ')).Count
$lock = $list -match 'locked claude'
"worktrees: $wt; lock line after claude -p ended: $lock"
($list -split "`n") | Where-Object { $_ -match '^locked' }
if ($wt -lt 2) { 'CANNOT CHECK (claude -w did not make a worktree: check that git is installed and claude -w works here)' } elseif ($lock) { 'REPRODUCED' } else { 'NOT REPRODUCED' }

なぜ起きるか

claude -w は、作った worktree に「claude session e1 (pid …)」というロックを付ける。-p で動かすと、終わったあともこのロックを外さない（公式 issue #111811）。git はロックの付いた worktree を remove も prune もしない。

直し方

片付ける前に、git worktree list --porcelain の locked の行の pid がもう動いていないかを確かめ、動いていないものだけ git worktree unlock してから remove する。動いている pid のロックは外さない。未コミットの変更が無いかも先に見る。

git worktree list --porcelain
# locked claude session ... (pid 1234) の 1234 が
Get-Process -Id 1234 -ErrorAction SilentlyContinue
# 何も出なければ
git worktree unlock <path>
git worktree remove <path>
