H06

Writing through a Windows 8.3 short name makes Claude Code drop the original file name

Symptom

app.settings.json or credentials.json is gone, and a file named APPSET~1.JSO or CREDEN~1.JSO is there instead, with the content Claude wrote. The tool reported success and never mentioned a rename.

Check it in 30 seconds

Paste into Windows PowerShell 5.1. It only creates files under your %TEMP% folder. If the last line says REPRODUCED, it happens on your machine. It calls claude once, so it takes about a minute.

$d = Join-Path $env:TEMP ('cc-trap-' + (Get-Date -Format 'yyyyMMddHHmmss')); New-Item -ItemType Directory $d -Force | Out-Null
Set-Content -LiteralPath "$d\app.settings.json" -Value old
$short = (cmd /c dir /x "$d" | Select-String 'app\.settings\.json' | ForEach-Object { ($_.Line -split '\s+') | Where-Object { $_ -match '~[0-9]' } } | Select-Object -First 1)
if (-not $short) { 'CANNOT CHECK (no 8.3 short name on this drive: dir /x shows none, so this cannot happen here)' } else {
"short name: $short"
Push-Location $d
"Use the Write tool once to overwrite the file $short in the current folder with the single line new. Use exactly that file name. Do not use any other tool. Do not retry." | claude -p --permission-mode bypassPermissions | Out-Null
Pop-Location
$long = Test-Path -LiteralPath "$d\app.settings.json"
$names = (Get-ChildItem -LiteralPath $d -Force | ForEach-Object { $_.Name }) -join ', '
"after the write: files = $names"
if ((-not $long) -and ($names -match [regex]::Escape($short))) { 'REPRODUCED' } else { 'NOT REPRODUCED' }
}

Why it happens

A Windows file can carry a second, short name (8.3 format) that dir /x shows. It is an alias for the same file, but when Claude Code's Write or Edit is given the short name, the long-named file is removed and a new file literally named with the short spelling is created (official issue #110153). It was refused in an acceptEdits claude -p run, but happens in bypassPermissions, which writes without asking.

Fix

Keep bypassPermissions to throwaway environments. If you use it on your own machine, add a PreToolUse hook that denies paths whose file-name part contains ~ followed by digits (call it with -File and add onFailure: block).

$p = [string]$j.tool_input.file_path
if ((Split-Path $p -Leaf) -match '~[0-9]+') { [Console]::Error.WriteLine('blocked: 8.3 short name'); exit 2 }
