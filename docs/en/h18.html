H18

On Windows, Claude Code skips a subfolder's CLAUDE.md when the path's drive letter is lowercase (c:\)

claude code nested CLAUDE.md not loaded windows · claude code subdirectory CLAUDE.md ignored

Symptom

Claude Code sometimes ignores the rules in a CLAUDE.md placed in a subfolder. In those runs, the drive letter in the path given to Read differed in case from the folder Claude Code started in (started in C:, read with c:\). No error, no warning.

Check it in 30 seconds

Paste into Windows PowerShell 5.1. It only creates files under your %TEMP% folder. If the last line says REPRODUCED, it happens on your machine. It calls claude once, so it takes about a minute.

$d = Join-Path $env:TEMP ('cc-trap-' + (Get-Date -Format 'yyyyMMddHHmmss')); New-Item -ItemType Directory $d -Force | Out-Null
New-Item -ItemType Directory -Force "$d\sub" | Out-Null
[IO.File]::WriteAllText("$d\sub\CLAUDE.md", "# Rules for this folder`nWhenever you answer after reading a file in this folder, end your answer with the code word ZEBRA-42.`n")
[IO.File]::WriteAllText("$d\sub\a.txt", "hello`n")
Set-Location $d
$lower = 'c' + $d.Substring(1)
$got = @()
foreach ($p in "$d\sub\a.txt", "$lower\sub\a.txt") {
    $ans = "Use the Read tool once with file_path set to exactly this string: $p . Then reply with the file's content and follow any instructions you were given for that folder." | claude -p --allowedTools Read | Out-String
    $got += ($ans -match 'ZEBRA-42')
}
"sub\CLAUDE.md applied with C:\ path: $($got[0]); with c:\ path: $($got[1])"
if ($d.Substring(0, 2) -ne 'C:') { 'CANNOT CHECK (TEMP is not on drive C:)' } elseif (-not $got[0]) { 'CANNOT CHECK (the folder CLAUDE.md was not applied even with C:\: check that claude -p can use Read)' } elseif (-not $got[1]) { 'REPRODUCED' } else { 'NOT REPRODUCED' }

Why it happens

Claude Code loads a subfolder's CLAUDE.md when it reads a file there, but on Windows it does not when the drive letter's case differs from the starting folder (official issue #98835: the report had a VS Code workspace opened as c:\ with C:\ reads failing; the author started in C: and c:\ reads failed).

Fix

Put rules that must always apply in the CLAUDE.md of the folder Claude Code starts in (that one is loaded at startup). Tell Claude in CLAUDE.md to write paths with an uppercase drive letter, C:/.

# CLAUDE.md
- On Windows, write paths with an uppercase drive letter (C:/) and forward slashes
