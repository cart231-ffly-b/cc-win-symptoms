C01

Codex CLI on PowerShell 5.1: non-ASCII text piped to a command arrives as ? (exit code 0)

codex cli windows question marks pipe · codex exec powershell non-ascii

Symptom

When Codex CLI pipes text with non-ASCII characters into a command such as python, the command receives ? instead. The command exits 0 and Codex does not notice. This happens on Windows without PowerShell 7, where Codex runs commands in Windows PowerShell 5.1.

Check it in 30 seconds

Paste into Windows PowerShell 5.1. It only creates files under your %TEMP% folder. If the last line says REPRODUCED, it happens on your machine.

$d = Join-Path $env:TEMP ('cc-trap-' + (Get-Date -Format 'yyyyMMddHHmmss')); New-Item -ItemType Directory $d -Force | Out-Null
$pyv = & python -c "import sys; print('%d.%d.%d' % sys.version_info[:3])" 2>$null
if (-not $pyv) { 'CANNOT CHECK (python not found, or only the Microsoft Store stub: install Python from python.org)' } else {
"python $pyv"
[IO.File]::WriteAllText("$d\hex.py", 'import sys; print(sys.stdin.buffer.read().strip().hex())')
$s = 'Zo' + [char]0xE9 + ' ' + [char]0x65E5 + [char]0x672C
$h = $s | python "$d\hex.py"
"bytes=$h  (UTF-8 would be 5a6fc3a920e697a5e69cac)"
if ($h -match '3f') { 'REPRODUCED' } else { 'NOT REPRODUCED' }
}

Why it happens

Without PowerShell 7, Codex runs commands with powershell.exe (5.1) -Command. PowerShell 5.1 encodes text sent to external commands with $OutputEncoding, which defaults to ASCII, so every non-ASCII character becomes ? (official issue openai/codex #64139). Same mechanism as T04.

Fix

Set $OutputEncoding to UTF-8 before piping. To have Codex do it, write the rule in the project's AGENTS.md (it helps but is not guaranteed).

$OutputEncoding = [Text.UTF8Encoding]::new($false)
'Zoé 日本' | python -c "import sys; print(sys.stdin.buffer.read().hex())"
