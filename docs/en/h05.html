H05

A Claude Code hook path written with backslashes never starts, and the write goes through (exit code 127)

claude code hook not running windows path · claude code hook 127

Symptom

You have a hook that denies writes, yet the file was written. Run by hand, the hook script does deny. The command in your settings is a backslash path such as C:\...\deny.cmd, or a path with a space and no quotes. No error, no warning.

Check it in 30 seconds

Paste into Windows PowerShell 5.1. It only creates files under your %TEMP% folder. If the last line says REPRODUCED, it happens on your machine. It calls claude once, so it takes about a minute.

$d = Join-Path $env:TEMP ('cc-trap-' + (Get-Date -Format 'yyyyMMddHHmmss')); New-Item -ItemType Directory $d -Force | Out-Null
$cmd = (@('@echo off', 'more > nul', 'echo x> "MARK"', 'exit /b 2') -join "`r`n").Replace('MARK', "$d\called.txt")
[IO.File]::WriteAllText("$d\deny.cmd", $cmd + "`r`n")
$fwd = '\"' + ($d -replace '\\', '/') + '/deny.cmd\"'
$back = ($d + '\deny.cmd') -replace '\\', '\\'
foreach ($k in @('fwd', 'back')) {
  $w = Join-Path $d $k; New-Item -ItemType Directory $w -Force | Out-Null
  $hook = if ($k -eq 'fwd') { $fwd } else { $back }
  [IO.File]::WriteAllText("$w\s.json", '{"hooks":{"PreToolUse":[{"matcher":"Write|Edit","hooks":[{"type":"command","command":"HOOK"}]}]}}'.Replace('HOOK', $hook))
  Push-Location $w
  'Use the Write tool once to create the file written.txt with the content hi. Do not retry if it is blocked.' | claude -p --settings s.json --permission-mode acceptEdits | Out-Null
  Pop-Location
  if ($k -eq 'fwd') { $c = Test-Path "$d\called.txt" }
}
$wf = Test-Path "$d\fwd\written.txt"; $wb = Test-Path "$d\back\written.txt"
"same deny.cmd: quoted C:/.../deny.cmd -> hook called=$c, written=$wf; unquoted C:\...\deny.cmd -> written=$wb"
if ((-not $c) -or $wf) { 'CANNOT CHECK (the quoted forward-slash hook did not block: check Git for Windows, disableAllHooks or your settings)' } elseif ($wb) { 'REPRODUCED' } else { 'NOT REPRODUCED' }

Why it happens

With Git for Windows installed, Claude Code runs a hook's command as a Git Bash command line. To bash, \ escapes the next character, so C:\Users\me\deny.cmd becomes C:Usersmedeny.cmd, a command that does not exist. An unquoted path with a space is split at the space. Both exit with 127 (command not found), and for PreToolUse anything other than 0 or 2 is a non-blocking error, so the write proceeds. Nothing shows in the claude -p result; the --debug log records status 127 (official issue #109103).

Fix

Write the path with forward slashes and wrap it in quotes (\" inside JSON). Give gate hooks "onFailure": "block" too, so a hook that cannot start also blocks (Claude Code 2.1.295 or later).

"command": "\"C:/Users/me/hooks/deny.cmd\"",
"onFailure": "block"
