H10

On Windows, Claude Code's Bash tool turns \\ (two backslashes) into one

Symptom

A script or regular expression that Claude Code wrote through the Bash tool has \ where it should have \\. It happens inside single quotes and inside quoted heredocs. No error; the broken text just runs.

Check it in 30 seconds

Paste into Windows PowerShell 5.1. It only creates files under your %TEMP% folder. If the last line says REPRODUCED, it happens on your machine. It calls claude once, so it takes about a minute.

$d = Join-Path $env:TEMP ('cc-trap-' + (Get-Date -Format 'yyyyMMddHHmmss')); New-Item -ItemType Directory $d -Force | Out-Null
[IO.File]::WriteAllText("$d\p.txt", 'Use the Bash tool once to run exactly this command and nothing else, then stop: printf ''%s'' ''a\\b'' > out.bin')
Push-Location $d
Get-Content "$d\p.txt" -Raw | claude -p --allowedTools Bash | Out-Null
Pop-Location
if (-not (Test-Path "$d\out.bin")) { 'CANNOT CHECK (out.bin was not written: check that the Bash tool is available and allowed)' } else {
$b = [IO.File]::ReadAllBytes("$d\out.bin")
"asked for a, two backslashes, b -> bytes written: " + (($b | ForEach-Object { '{0:x2}' -f $_ }) -join ' ')
if ($b.Length -eq 3) { 'REPRODUCED' } else { 'NOT REPRODUCED' }
}

Why it happens

On Windows (Git for Windows), Claude Code's Bash tool turns each \\ in the command into a single \ before running it. The command the model sent has two (the transcript shows it). Four become two, a single one stays single (official issue #110308).

Fix

Do not put text with backslashes (scripts, regular expressions, Windows paths) in Bash commands or heredocs. Save it to a file with the Write tool first, and write Windows paths with forward slashes.

# save the text with the Write tool, and let the command only read the file
python fix.py
