H14

On Windows, Claude Code's Bash tool does not run commands longer than about 7,400 characters (the error says a quote is unmatched)

unexpected EOF while looking for matching claude code · claude code bash long command fails windows

Symptom

When Claude Code runs a long heredoc or script with the Bash tool, nothing runs and it gets unexpected EOF while looking for matching, a quoting error, although the command has no quoting mistake. With text made mostly of single quotes, it happens at about 1,500 characters.

Check it in 30 seconds

Paste into Windows PowerShell 5.1. It only creates files under your %TEMP% folder. If the last line says REPRODUCED, it happens on your machine. It calls claude once, so it takes about a minute.

$d = Join-Path $env:TEMP ('cc-trap-' + (Get-Date -Format 'yyyyMMddHHmmss')); New-Item -ItemType Directory $d -Force | Out-Null
$hook = @'
import json, sys
from pathlib import Path
d = json.load(sys.stdin)
if d.get("tool_name") != "Bash":
    sys.exit(0)
n = int(Path("n.txt").read_text().strip())
cmd = "printf %s '" + "A" * n + "' > o.txt; echo ok > d.txt"
print(json.dumps({"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "allow", "updatedInput": {"command": cmd}}}))
'@
[IO.File]::WriteAllText("$d\hook.py", $hook)
$hp = ($d + '\hook.py').Replace('\', '/')
[IO.File]::WriteAllText("$d\s.json", '{"hooks":{"PreToolUse":[{"matcher":"Bash","hooks":[{"type":"command","command":"python \"HP\""}]}]}}'.Replace('HP', $hp))
$ok = @{}
Push-Location $d
foreach ($n in 7000, 7600) {
    Remove-Item -LiteralPath "$d\o.txt", "$d\d.txt" -ErrorAction SilentlyContinue
    [IO.File]::WriteAllText("$d\n.txt", "$n")
    'Use the Bash tool once to run: echo hi . Then stop.' | claude -p --settings s.json --allowedTools Bash | Out-Null
    $ok[$n] = (Test-Path "$d\d.txt")
}
Pop-Location
"a 7000-A command ran to the end: $($ok[7000]); a 7600-A command ran to the end: $($ok[7600])"
if (-not $ok[7000]) { 'CANNOT CHECK (even the 7000-character command did not run: check that python is installed and the Bash tool works)' } elseif (-not $ok[7600]) { 'REPRODUCED' } else { 'NOT REPRODUCED' }

Why it happens

On Windows, Claude Code wraps the Bash tool command in setup and cleanup code and passes it as one bash.exe -c string. Git for Windows bash keeps only the first 8,186 characters of that string and drops the rest (official issue #102533). After the wrapper, about 7,400 characters are left for the command on the author's PC. According to the issue, each single quote is rewritten as five characters.

Fix

Write long scripts and heredocs to a file with the Write tool, then run them with a short command such as bash script.sh. Say so in CLAUDE.md.

# CLAUDE.md
- On Windows, do not put long scripts or heredocs in Bash tool commands (the limit is in the 7,000s; a single quote counts as 5)
- Write anything over a few thousand characters to a file with the Write tool and run bash <file>
