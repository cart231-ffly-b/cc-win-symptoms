H17

Start Claude Code in a repo subfolder and the hooks in the root .claude/settings.json do not run

Symptom

A hook in the repo root .claude/settings.json that blocks writes sometimes does nothing. In those runs, an editor terminal or a script started claude in a folder below the repo root. No error, no warning.

Check it in 30 seconds

Paste into Windows PowerShell 5.1. It only creates files under your %TEMP% folder. If the last line says REPRODUCED, it happens on your machine. It calls claude once, so it takes about a minute.

$d = Join-Path $env:TEMP ('cc-trap-' + (Get-Date -Format 'yyyyMMddHHmmss')); New-Item -ItemType Directory $d -Force | Out-Null
$repo = Join-Path $d 'hookrepo'
New-Item -ItemType Directory -Force "$repo\.claude", "$repo\sub\deep" | Out-Null
Push-Location $repo; git init -q 2>$null; Pop-Location
$mark = ($repo + '\hook-ran.txt').Replace('\', '/')
$cmd = 'python -c "open(r''' + $mark + ''',''a'').write(''x'')"'
$settings = @{ hooks = @{ PreToolUse = @(@{ matcher = 'Read'; hooks = @(@{ type = 'command'; command = $cmd }) }) } } | ConvertTo-Json -Depth 8
[IO.File]::WriteAllText("$repo\.claude\settings.json", $settings)
[IO.File]::WriteAllText("$repo\sub\deep\a.txt", "hello`n")
[IO.File]::WriteAllText("$repo\a.txt", "hello`n")
$ran = @{}
foreach ($where in 'root', 'sub\deep') {
    Remove-Item -LiteralPath "$repo\hook-ran.txt" -ErrorAction SilentlyContinue
    Push-Location (Join-Path $repo ($where -replace 'root', ''))
    'Use the Read tool once on a.txt and reply done.' | claude -p --allowedTools Read | Out-Null
    Pop-Location
    $ran[$where] = Test-Path "$repo\hook-ran.txt"
}
"root hook ran when started at the repo root: $($ran['root']); when started in sub\deep: $($ran['sub\deep'])"
if (-not $ran['root']) { 'CANNOT CHECK (the hook did not run even at the root: check that python and git are installed)' } elseif (-not $ran['sub\deep']) { 'REPRODUCED' } else { 'NOT REPRODUCED' }

Why it happens

As documented, the shared .claude/settings.json is read from the folder Claude Code starts in. .claude/settings.local.json normally comes from the repo root, but on Windows it is also read from the starting folder. Plugins installed with --scope local are disabled in subfolders for the same reason (official issue #106149).

Fix

Put hooks that must always run in the user settings (~/.claude/settings.json). In unattended scripts, Push-Location to the repo root before calling claude -p.

Push-Location C:/work/repo   # the folder that holds .claude/settings.json
$prompt | claude -p
Pop-Location

On the author's machine

a PreToolUse hook in the root .claude/settings.json ran when claude was started at the root and did not run when started in sub/deep; the same with .claude/settings.local.json (2026-11-25, Claude Code 2.1.330, Windows 11)

Author's machine: Windows 11 / Windows PowerShell 5.1.26100 / Python 3.13.7 / Claude Code 2.1.304, Japanese Windows (code page 932). Checked 2026-10-20 to 22.
