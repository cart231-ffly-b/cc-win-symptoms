H07

Stopping a background Bash task in Claude Code with TaskStop leaves the processes started with & or a pipe running

Symptom

You had Claude Code run a Bash command in the background and stop it with TaskStop, and claude -p has exited, but sleep.exe, cat.exe or timeout.exe are still in Task Manager. With tail -f or a loop they never end, slow the PC down, and can collide with the next night's run.

Check it in 30 seconds

Paste into Windows PowerShell 5.1. It only creates files under your %TEMP% folder. If the last line says REPRODUCED, it happens on your machine. It calls claude once, so it takes about a minute.

$d = Join-Path $env:TEMP ('cc-trap-' + (Get-Date -Format 'yyyyMMddHHmmss')); New-Item -ItemType Directory $d -Force | Out-Null
[IO.File]::WriteAllText("$d\p.txt", "Do exactly these steps and nothing else:`n1. Use the Bash tool with run_in_background set to true to run exactly this command: sleep 123 & timeout 124 sleep 122 & sleep 125 | cat`n2. Use the TaskStop tool to stop that background task.`n3. Reply STOPPED and the task id.")
Push-Location $d
$o = Get-Content "$d\p.txt" -Raw | claude -p --allowedTools "Bash,TaskStop" | Out-String
Pop-Location
Start-Sleep -Seconds 3
$left = @(Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -match 'sleep(\.exe)?"?\s+12[235]\b' })
"claude said: $($o.Trim())"
"processes still running after claude -p ended: $($left.Count)"
$left | ForEach-Object { '  ' + $_.ProcessId + ' ' + $_.CommandLine }
'(leftover sleep processes end by themselves within about two minutes)'
if ($o -notmatch 'STOPPED') { 'CANNOT CHECK (claude did not report STOPPED: check that the Bash and TaskStop tools are available and allowed)' } elseif ($left.Count -gt 0) { 'REPRODUCED' } else { 'NOT REPRODUCED' }

Why it happens

On Windows, when TaskStop stops a background Bash task, Claude Code stops the top bash but not the processes it started with & or a pipe (official issue #109388). They stay running under Git's usr/bin after claude -p exits.

Fix

Give background commands a timeout (timeout 20 sleep 301 removes itself when time is up). From time to time, list the processes under Git's usr/bin with the command below and look for leftovers. For unattended night runs, detect processes left after a run and stop the next run.

Get-CimInstance Win32_Process | Where-Object { $_.ExecutablePath -like '*\Git\usr\bin\*' } | Select-Object ProcessId, CommandLine

On the author's machine

with sleep 123 & timeout 124 sleep 122 & sleep 125 | cat run as a background Bash task in claude -p and stopped with TaskStop, all five (three sleep, timeout, cat) were still running 3 seconds after claude -p exited; with timeout 20 sleep 301, two were left after TaskStop and both were gone 20 seconds later (2026-11-24, Claude Code 2.1.330, Git for Windows)

Author's machine: Windows 11 / Windows PowerShell 5.1.26100 / Python 3.13.7 / Claude Code 2.1.304, Japanese Windows (code page 932). Checked 2026-10-20 to 22.
